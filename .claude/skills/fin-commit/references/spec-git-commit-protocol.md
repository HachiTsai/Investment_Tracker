# 財商工程 Git Commit 規格書（SSOT）

> 本檔是 commit 規範的唯一真實來源。`scripts/committer.py` 的檢查規則與草擬指令皆以本檔為準；修改規範時，兩者須同一 commit 更新。

## 1. 總則

- 所有 commit 使用**同一份詳細模板**（§4）。類別、type、scope 由 committer 依 staged 路徑自動判定，不逐次詢問使用者。
- **交易紀錄只是其中一種 commit**：它與其他 commit 共用模板，只是多了必填的「交易明細」區塊。
- 一個 commit 只承載一個投資事件或一個主題。混了多種行為（例如股利入帳後再投入）就拆成多個 commit。
- 數字以 Investment_Tracker_Core 為準，取不到的數字詢問使用者，不得推測。Core **嚴禁修改**（見 CLAUDE.md）。

## 2. 類別（Session-Sync「類別」欄）

| 類別 | 判定路徑 | 說明 |
| --- | --- | --- |
| 交易紀錄 | `portfolio/transactions/` | 買進、賣出、再投入、換股、股利、資金進出 |
| 持股分析 | `portfolio/`（其餘） | 快照、行情、目標追蹤 |
| 財商架構 | `architecture/` | 目標、配置、現金流模型、決策規則 |
| 投資研究 | `research/`、`journal/` | 標的研究與論點、投資日誌 |
| 趨勢覺察 | `trends/` | 產業、總經、市場趨勢的覺察 |
| IT | 其餘（`scripts/`、`.claude/`、`CLAUDE.md`…） | 工具、投資管理 skill、規範、文件 |

混合多類別時，依上表由上而下的順序取第一個。

可用 `--category` 手動覆蓋。

## 3. Type 與 Scope

### 3.1 Type

| 群組 | type | 中文 | 額外必填區塊 |
| --- | --- | --- | --- |
| 交易 | `buy` | 買進 | 交易明細 |
| 交易 | `sell` | 賣出 | 交易明細（含 損益） |
| 交易 | `reinvest` | 股息再投入 | 交易明細 |
| 交易 | `rebal` | 換股／再平衡 | 交易明細（賣出、買入） |
| 現金流 | `div` | 股利（除息、入帳） | 股利明細 |
| 現金流 | `cash` | 入金、出金、預備金 | — |
| 現金流 | `fee` | 手續費、稅、二代健保 | — |
| 分析 | `snap` | 持股快照 | — |
| 分析 | `price` | 股價、殖利率、匯率更新 | — |
| 分析 | `goal` | 目標數字調整（如年股利目標） | — |
| 思考 | `arch` | 財商工程架構：配置、現金流、決策規則 | — |
| 思考 | `research` | 標的研究、投資論點、試算 | — |
| 思考 | `trend` | 趨勢覺察 | — |
| 思考 | `journal` | 投資日誌、決策回顧 | — |
| 維運 | `fix` | 資料或程式修正 | — |
| 維運 | `tool` | `scripts/`、投資管理 skill 的新增與修改 | — |
| 維運 | `docs` | CLAUDE.md、規範、說明文件 | — |
| 維運 | `chore` | 雜項 | — |

選 type 的優先順序：**實際發生的投資行為 > 資料狀態 > 維運**。重大策略轉向在 type 後加 `!`（如 `goal!(portfolio): ...`）。

### 3.2 Scope

- 單一標的：代號，如 `00882`；多標的以 `,` 分隔，如 `00877,00882`。
- 非單一標的：主題，如 `portfolio`、`architecture`、`trends`、`claude`，或 skill 名稱如 `fin-commit`。

### 3.3 標題

`<type>(<scope>): <摘要>`：摘要用繁體中文，≤ 50 字，寫「做了什麼＋關鍵數字」，結尾不加句號。

## 4. 模板（唯一版本）

```markdown
<type>(<scope>): <摘要>

## 核心變更

- 具體變更

## 變更理由

- 為什麼要做／解決了什麼問題

## 交易明細（交易類 buy/sell/reinvest/rebal 必填，其餘刪除本區塊）

- **日期**: YYYY-MM-DD
- **數量**: 10,000 股（10 張）
- **價格**: 15.08
- **金額**: 150,800 TWD
- **手續費**: 215
- **損益**: +xxx TWD（+x.xx%）      ← sell 必填
- **賣出**: ... / **買入**: ...        ← rebal 用這兩欄取代 數量/價格/金額
- **理由**: 一句話
- **來源**: Core/Transactions Tx_ID xxx

## 股利明細（div 必填，其餘刪除本區塊）

- **日期**: YYYY-MM-DD（除息日／入帳日）
- **每股配息**: 0.55
- **實收**: 158,344 TWD
- **年度累計**: 276,244 TWD

## 驗證

- **執行裝置**: （committer 自動補上）
- 數字核對：數量 × 價格 = 金額；與 Core 對照的分頁與 Tx_ID
- 純文件變更明寫「無需驗證—純文件變更」，不可省略本區塊

## 目標影響（選用：會改變年股利推估時填；交易類強烈建議）

- 年股利推估 300,000 → 315,000（缺口 200,000 → 185,000），假設：…

## 關鍵決策（選用：有取捨時填）

| 選項 | 為什麼沒選 | 為什麼選現在這個 |
| :--- | :--- | :--- |

## Pending Tasks（選用）

- 待辦事項，例如「試算表 Portfolio!E2 殖利率待 Hachi 更新」

## Session-Sync

- **執行者**: （committer 偵測）
- **類別**: （committer 判定）
- **狀態**: 當前狀態
- **下一步**: 下一步
- **阻塞**: 無／具體 blocker
```

## 5. 檢查規則（committer 執行）

### 錯誤（擋下提交）

- 暫存區的 `.md` 未通過 markdown-linter（`.markdownlint-cli2.jsonc`）。
- 標題不符 `<type>(<scope>): <摘要>`、type 不在 §3.1、摘要 > 50 字或結尾有句號、標題後未空一行。
- 交易類缺「## 交易明細」或其必填欄位；`div` 缺「## 股利明細」或其必填欄位。
- 數量 × 價格 與 金額 相差 > 1。
- 「日期」不是 `YYYY-MM-DD` 開頭。

### 警告（不擋）

- 缺「核心變更」「變更理由」「驗證」「Session-Sync」。
- 交易類缺「目標影響」。

`Merge` / `Revert` / `fixup!` / `squash!` 開頭的訊息不檢查。

## 6. 快速提交（`--auto-quick`）

純機械式精簡提交，由路徑推斷 type 與 scope，Session-Sync 狀態欄填佔位語。**以下情況禁止**（改走完整模板）：

- 類別為「交易紀錄」——交易需要明細與核對，不能機械生成。
- 暫存區含 `CLAUDE.md` 或 `.claude/skills/fin-commit/`——規範本體的變更需要說明理由。

確認屬純格式修正時可加 `--allow-guarded` 解除。

## 7. 查詢

```bash
git log --oneline --grep '^div'                            # 所有股利
git log --oneline --grep '(00882)'                         # 00882 相關事件
git log --oneline -E --grep '^(buy|sell|reinvest|rebal)'   # 所有交易
git log --grep '類別\*\*: 交易紀錄'                         # 依 Session-Sync 類別
```
