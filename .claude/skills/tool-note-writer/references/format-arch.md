# 財商架構筆記格式（type: arch）

> `notes.py new arch` 產生的空白筆記與 `notes.py check` 的檢查規則，皆以本檔為準。

## 檔名

- 位置：`architecture/<title>.md`，檔名主幹必須與 frontmatter 的 `title` 完全相同（Obsidian 以檔名作為連結目標）。
- **不使用日期**：檔名不可含 `YYYY-MM-DD` 或 `YYYYMMDD`。日期寫在 `created`／`updated` 欄位與變更紀錄裡。
- 用名詞片語描述「這是什麼規則」，例如 `股利目標模型`、`單一標的集中度上限`、`股息再投入規則`。
- 不可含空白與 `* " \ / < > : | ? # ^ [ ]`；需要分隔時用 `-`。

## Frontmatter

只使用下列欄位，每個欄位一行，清單寫成 `[a, b]` 的單行形式（方便 grep，Obsidian Properties 也能正確顯示）。

| 欄位 | 必填 | 格式 | 說明 |
| --- | --- | --- | --- |
| `type` | ✓ | `arch` | 筆記類型 |
| `title` | ✓ | 文字 | 與檔名相同 |
| `domain` | ✓ | 詞彙表 `domain` 擇一 | 所屬領域 |
| `status` | ✓ | 詞彙表 `status` 擇一 | 草稿／生效／修訂中／廢止 |
| `version` | ✓ | 正整數 | 規則版本，與「變更紀錄」最新一筆一致 |
| `created` | ✓ | `YYYY-MM-DD` | 建立日 |
| `updated` | ✓ | `YYYY-MM-DD` | 最後實質修改日，不早於 `created` |
| `tags` | ✓ | `[詞, ...]`，詞彙表 `tags` | 至少一個 |
| `review` |  | `YYYY-MM-DD` | 下次回頭檢查這條規則的日期 |
| `tickers` |  | `[00882, ...]` | 相關標的代號 |
| `related` |  | `["[[筆記名]]", ...]` | 相關筆記，Obsidian wikilink 需加引號 |
| `aliases` |  | `[別名, ...]` | 搜尋用別名（Obsidian 原生欄位） |
| `sources` |  | `[URL或來源, ...]` | 依據來源 |

## 正文段落

不寫 `# 標題`：Obsidian 以檔名顯示標題，frontmatter 的 `title` 也已被 markdownlint 視為 H1，再寫一次會觸發 MD025。正文必須通過 markdown-linter 檢查（`notes.py check` 會自動執行）。

依序使用以下 `##` 段落，名稱不可更改（搜尋與檢查都依賴它們）：

1. `## 摘要`：一到兩句話說清楚這條規則。搜尋結果會顯示這段，要讓人不打開全文也懂。
2. `## 規則`：具體、可執行的條文，用編號列出；有數字就寫數字（例如「單一標的 ≤ 60%」）。
3. `## 理由`：為什麼這樣定；區分「事實／數據（附來源與日期）」與「判斷／觀點」。
4. `## 適用範圍與例外`：何時適用、何時不適用。
5. `## 變更紀錄`：每個版本一個 `### v<版本>（YYYY-MM-DD）` 小節，寫「變更」與「原因」。

## 修改規則時

- 規則有實質變更：`version` +1、更新 `updated`，在「變更紀錄」新增一節。
- **不刪除舊規則**：被取代的條文移到該版本的變更紀錄中保留，讓日後看得到當初怎麼想、為什麼改。
- 只修錯字或排版：不升版，不需新增變更紀錄。
- 規則不再使用：`status` 改為 `廢止`，檔案保留。

## 範例

```markdown
---
type: arch
title: 股利目標模型
domain: 目標
status: 生效
version: 1
created: 2026-10-01
updated: 2026-10-01
tags: [股利, 高股息, 複利]
review: 2027-01-15
tickers: [00882]
related: ["[[股息再投入規則]]"]
aliases: [年股利50萬目標]
---

## 摘要

以每年股利收入 500,000 TWD 為目標，用「缺口 ÷ 殖利率」估算還需投入的本金。

## 規則

1. 目標：年股利實收 ≥ 500,000 TWD。
2. 年股利推估 = 持股數 × 近一年每股配息（假設配息持平）。
3. 需追加本金 = (目標 − 推估) ÷ 現行殖利率。

## 理由

- 事實（2026-10-01 快照）：00882 300 張、年配 1.00、殖利率 6.74%，推估 300,000。
- 判斷：以殖利率倒推本金，比以報酬率估算更貼近「現金流」目標。

## 適用範圍與例外

- 適用：以股利收入為主要目標的配置。
- 例外：配息大幅變動（±20% 以上）時，改用最近四季實際配息重估。

## 變更紀錄

### v1（2026-10-01）

- 變更：建立模型。
- 原因：建立財商工程大本營，將目標量化。
```
